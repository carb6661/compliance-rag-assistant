# 配置、诊断与入库约定

## 标题识别

本项目使用 markdown-it-py 的 heading token 与 map 行号，维护标题栈，属于标题层级切分。没有使用固定字符窗口代替层级，也没有用文本搜索推测位置。

相比直接使用 MarkdownHeaderTextSplitter，本实现需要同时保留原文区间、表格/列表/围栏及语义字段作用域，因此使用语法树自行实现切分；最终仍返回 LangChain Document。普通段落超过目标时可再切分，原子结构只警告不破坏。

标题移除形如“7 ”“7.1 ”“7.1.1. ”的编号前缀再匹配；不会删除标准名称内部数字。支持 ATX、Setext 及 Markdown 强调内的可见标题文字。代码围栏、列表和引用中的标题不改变全局上下文。HTML 标题不作为结构解析，也不渲染。

## 配置字段

- standards：实际标题到 name/code/edition/synthetic 的映射；同一标准可提供多个不同别名。
- level_aliases：实际级别标题到第一级至第五级的规范值。传入该字段时替换默认表，不与默认隐式合并。
- security_classes：安全类精确清单，默认十类。
- requirement_types：通用及扩展要求的精确清单；没有明确标题时元数据为空字符串，不推断。
- excluded_headings：明确不入库的章节，默认前言、引言、目录、参考文献；排除及范围必须人工确认。
- max_chars：64—20,000，默认1,200，单位为Python字符，不是token。

不接受任意正则或Python插件配置。规范化后的别名重叠会拒绝，以免一个标题同时被当作级别和安全类。标准配置不是官方认证或版权授权。

## 作用域与诊断

同级或更高标题出现时退出旧节点。识别新标准重置级别/要求类型/类别；新级别重置要求类型和类别；新要求类型重置类别。未识别标题仍保留在路径里，但不能凭它补出必填字段。

- MISSING_METADATA：正文缺标准、级别或安全类，error。
- UNSCOPED_BODY：首个标题前有未归类正文，error。
- NO_DOCUMENTS：没有任何可入库正文，error。
- EXCLUDED_SECTION：处于显式排除章节，info，保留范围但不导出正文。
- OVERSIZE_ATOMIC：不可破坏结构超过字符目标，warning；仍导出完整块。

严格模式阻止整个批次写新的JSONL；有效候选块数量仍在诊断里，便于定位。部分模式仅导出有效候选块，返回1，必须由调用方明确接受这种覆盖缺口。

## 退出码与输出安全

0=成功；1=明确允许部分导出但仍有结构错误；2=严格失败、输入/配置/IO或参数错误。API 的 partial 使用200/status=partial，和CLI退出码语义不同，调用方要检查业务状态。

不指定 --out 就只检查。输出与输入、配置、其他输出路径冲突会拒绝。默认不覆盖已存在文件，--force 只表示允许覆盖指定结果，不允许覆盖输入；输入及输出符号链接拒绝。每个结果文件通过同目录临时文件发布，未使用 --force 时原子创建且不覆盖竞争写入；本地文件系统需支持硬链接。

每文件与批次边界独立，不从前一个文件继承标题。单个文件语法错或超限会中止批次，已生成文档不会写入新的导出；跨多个输出文件的IO写入不是事务，可能已有诊断文件，因此应检查最终退出码。

## 后续RAG接入

用 embedding_text 显式为嵌入文本补充父标题，用独立metadata字段实现检索过滤；回答时引用标准版本、源文件、行号、源摘要和块ID。不要把这些描述字段当成大模型系统指令，也不要把来源 unverified 改成 verified 而没有审核过程。

本阶段不产生通过/不通过测评结论。检索、证据匹配、更新版本和人工复核将另行实现，不把规划当作已交付功能。
